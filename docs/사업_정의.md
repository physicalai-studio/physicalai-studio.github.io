## 1. 한 문장

> **We build the world, not the brain.**

조금 더 정확히는 — **세계와, 그 안에서 지능을 개발하기 위해 필요한 인터페이스**를 만든다.

고객은 로봇을 가져온다. 고객은 지능을 가져온다.
우리는 **둘이 실패해도 아무것도 부서지지 않는 세계**를 먼저 만든다.
그 세계를 수백 번 통과하고도 살아남은 것만 현실의 문을 열고 나간다.

파는 것은 시뮬레이션 영상도, 시나리오 프로그램 한 건도 아니다.
고객이 이후에도 새 알고리즘 · 정책 · 센서 · 로봇 · 시나리오를 붙여 계속 연구할 수 있는
**실행 가능한 디지털 테스트베드(Digital Testbed)** 다.

## 2. 역할 경계 — 누가 무엇을 하는가

**이 문서에서 가장 중요한 절이다.** 경계가 흐려지면 사업이 다른 업으로 미끄러진다(§9).

| 우리의 영역 (세계)                                        | 고객의 영역 (지능)                        |
| --------------------------------------------------------- | ----------------------------------------- |
| 디지털 자산 — CAD/STEP/URDF → OpenUSD, 관절 · 충돌 · 질량 | Navigation · Manipulation · Task Planning |
| 물리와 센서 시뮬레이션                                    | RL · IL · VLA · World Foundation Model    |
| ROS2 / API 인터페이스, Observation · Action               | Vision 알고리즘, 고객 고유 AI             |
| Reset · Spawn · Randomization · Ground Truth              | 로봇 제품 소프트웨어                      |
| 로깅 · 지표 · 검증 · 재현 가능한 배포(Docker)             | **최종 제품 지능의 성능**                 |

### Reference Implementation ≠ Product Intelligence

환경이 제대로 도는지 보이기 위해 **참조 동작**은 제공한다 — waypoint 이동, MoveJ · MoveL,
단순 pick · place, 단순 주행. 이것은 고객 제품의 지능을 대신 개발한다는 뜻이 **아니다.**
이 경계가 사업이 일반 로봇 개발 용역으로 변질되는 것을 막는다.

## 3. 하지 않는 일 (먼저 못박는다)

포지셔닝은 하는 일보다 **안 하는 일**로 더 분명해진다.

| 하지 않는다                          | 이유                                                      |
| ------------------------------------ | --------------------------------------------------------- |
| **로봇 · 제어 소프트웨어 개발 대행** | 로봇과 지능은 고객의 것이다 (§2)                          |
| **현장 로봇 튜닝 · PLC · 비전 대행** | 받기 시작하면 로봇 잡다한 용역 회사로 되돌아간다          |
| **홍보용 3D 영상 · 애니메이션**      | 결론을 만들지 않는 산출물                                 |
| 현장 SI 파견 · 상주 인력 제공        | 인시(人時)를 파는 일. 이 사업의 가치는 시간이 아니라 판단 |
| 설비 제작 · 시공 · 납품              | 제조가 아니라 검증 환경이 업이다                          |
| 근거 없는 "가능합니다" 답변          | §6 신뢰 등급 없이 결론을 팔지 않는다                      |

> **"이 구조로는 안 된다"도 정상 산출물이다.** 제작 전에 아는 것이 이 사업이 파는 가치다.

## 4. 고객 — 누구에게 파는가

가장 정확한 정의 한 줄:

> **실물 로봇 또는 Physical AI 기술은 가지고 있지만, 그것을 반복적으로 개발 · 검증 · 연구할
> 디지털 환경이 없는 팀.**

| 고객군                    | 가지고 있는 것            | 문제                               | 우리가 주는 것                  |
| ------------------------- | ------------------------- | ---------------------------------- | ------------------------------- |
| **로봇 스타트업 · OEM**   | 로봇팔 · AMR · 휴머노이드 | 실기에서만 테스트해 실험 비용이 큼 | 재사용 가능한 디지털 테스트베드 |
| **로봇 SI · 자동화 업체** | 로봇 + 설비 설계          | 제작 전 성립 여부가 불확실         | 타당성 검토 · 가상 시운전       |
| **대학 · 연구기관**       | 알고리즘 · 연구 인력      | 연구보다 환경 구축에 시간이 간다   | 재현 가능한 연구 환경           |
| **제조 R&D**              | 실제 공정과 설비          | 도입 전 검증이 필요                | 타당성 검토 + 디지털 트윈       |
| **Physical AI 팀**        | RL · VLA · WFM 모델       | 학습 · 평가할 물리 환경이 없다     | 지능이 들어갈 몸과 세계         |

**첫 고객은 아는 생태계에서 찾는다** — AMR · 로봇팔 · 휴머노이드 · 연구기관 · 로봇 SI.

### 잠재 고객을 식별하는 문장 (Pain 이 이미 있는 팀)

이 말이 나오면 거의 고객이다. **사이트는 이 문장들을 그대로 보여준다** — 방문자가
자기 상황을 문장으로 알아보는 것이 가장 빠른 자격 판정이다.

- "환경 구축할 사람이 없어서 실제 로봇에서만 테스트하고 있습니다."
- "시뮬레이션을 해보고 싶긴 한데 사람이 없습니다."
- "URDF 는 있는데 시뮬레이터에서 제대로 안 돌아갑니다."
- "실제 장비가 아직 안 나왔는데 소프트웨어부터 개발해야 합니다."
- "연구를 하고 싶은데 환경 구축이 너무 오래 걸립니다."
- "고객마다 시뮬레이션을 처음부터 다시 만들고 있습니다."

## 5. 제품 사다리

처음부터 가장 복잡한 것만 팔지 않는다. 진입 단계를 셋으로 둔다.

| 제품                            | 고객의 질문                    | 받는 것                                                                 |
| ------------------------------- | ------------------------------ | ----------------------------------------------------------------------- |
| **A. 시뮬레이션 타당성 검토**   | 이 로봇으로 이 작업이 되는가?  | 디지털 환경 · 참조 동작 · 도달성 · 충돌 · 작업영역 · 근거               |
| **B. 재사용 디지털 테스트베드** | 매번 다시 만들지 않으려면?     | 로봇 · 환경 · 물리 · 센서 · ROS2/API · 시나리오 · Reset · 지표 · Docker |
| **C. Physical AI 연구 환경**    | 지능을 여기서 학습·평가하려면? | + Randomization · Ground Truth · 데이터셋 · 평가 · 학습 인터페이스      |

**B 가 이 사업의 핵심 상품이다.** A 는 가장 쉬운 진입, C 는 고급 연구 고객.

### 성숙도 — 무엇을 파는지 헷갈리지 않기 위해

| 단계              | 무엇                                                |
| ----------------- | --------------------------------------------------- |
| L1 디지털 자산    | 디지털 공간에 존재하는 물체                         |
| L2 실행 가능 자산 | 움직이고 반응하는 물체 (물리 · 센서 · 인터페이스)   |
| **L3 연구 환경**  | **지능과 연구가 들어올 수 있는 환경 — 우리의 목표** |
| L4 Physical AI    | 고객의 정책이 직접 상호작용 (고객의 영역)           |

## 6. 차별점 — 이 넷이 전부다

넷 모두 **로봇을 아는 사람이 시뮬레이션을 만들 때만** 나온다.
어떤 값이 결론을 좌우하는지, 어떤 자세가 구조적으로 위험한지, 무엇을 재야 실기와 대조되는지를
알아야 등급을 매기고 · 항목을 고르고 · 한계를 특정할 수 있다.

### ① 재현성이 곧 품질이다

> **Reproducibility is Quality.**

"내 PC 에서 잘 됩니다"는 품질이 아니다. 기준은 하나다 —
**다른 연구자가 다른 PC 에서 같은 실험을 다시 실행할 수 있는가.**
그래서 Docker · 의존성 · 설정 · 버전 · 실행 구조가 산출물에 포함된다.

### ② 충실도를 선언한다

"실제와 같습니다"라고 말하지 않는다. 무엇을 어느 수준까지 표현했는지 층으로 밝힌다.

| 층           | 무엇                             |
| ------------ | -------------------------------- |
| F1 형상      | 치수 · 배치 · 위치               |
| F2 기구학    | 관절 · 작업영역 · 한계 · 도달성  |
| F3 물리      | 질량 · 충돌 · 접촉 · 마찰 · 관성 |
| F4 센서      | 카메라 · LiDAR · IMU · 인지 조건 |
| F5 시스템    | ROS2 · 컨트롤러 · 통신 · 시퀀스  |
| F6 실기 상관 | 실제와 시뮬레이션 결과의 대조    |

**모든 프로젝트가 F6 를 요구하지 않는다.** 질문에 답할 만큼 충분한 충실도를 고르는 것이 일이다.

### ③ 신뢰 등급을 함께 준다

결론만 주지 않는다. **그 결론이 어떤 값 위에 서 있는지**를 등급으로 표시한다.

| 등급          | 뜻                               |
| ------------- | -------------------------------- |
| **실측**      | 도면 · 실물에서 직접 잰 값       |
| **형상 산출** | 형상에서 역산한 값 (사양서 아님) |
| **추정**      | 동작하도록 고른 값               |
| **미확보**    | 사양서가 필요한 값               |

> "위치 제어에 대한 결론은 믿어도 된다. 그러나 **힘 · 토크 · 파지력에 관한 어떤 결론도 이 모델에서
> 끌어내면 안 된다** — 질량과 관성이 추정값이다."

### ④ 한계를 먼저 선언한다

알려진 결함을 목록으로 넘긴다 — 미확보 사양, 특이 자세, 충돌체 누락, 축 이름 불일치.
숨기면 사고가 나고, 밝히면 신뢰가 된다.

## 8. 일하는 방식 — 다섯 개의 문

업무 순서가 아니라 **아이디어가 현실이 되기 위해 통과해야 하는 관문**이다
(전문: [how_we_work.md](how_we_work.md), 결정: [ADR-0009](adr/0009-how-we-work-as-gates.md)).

> **FROM ASSUMPTION TO EVIDENCE.** — 가정을 근거로 바꾼다.

1. **가정을 의심한다** — 고객이 가져온 설계 · 사이클 타임 · 동작 방식을 가설로 둔다.
2. **현실을 모델로 만든다** — 복제품이 아니라 질문에 답하기 위한 표현. 충분히 진실한 모델.
3. **물리가 가능성을 제한하게 한다** — 원하는 답을 강요하지 않고, 불가능한 것을 말하게 한다.
4. **가능성의 경계를 찾는다** — PASS/FAIL 이 아니라 어디까지 되는지. 우리가 파는 것은 경계다.
5. **증명을 현실로 넘긴다** — 재현 절차와 함께. 넘어가지 못하는 증명은 증명이 아니다.

## 9. 이 사업이 실패하는 방향

1. **경계가 무너지는 순간** — 로봇·지능 개발을 대신 하기 시작하면 우리가 병목이 되고,
   세계를 파는 대신 손을 파는 일로 미끄러진다(§2 · §3).
2. **재현성이 빠지는 순간** — "내 PC 에서 됩니다"는 자산이 아니다. 다음 프로젝트에서 다시 만든다.
3. **신뢰 등급 없이 결론만 파는 순간** — 일반 시뮬레이션 용역과 구분이 사라진다.
4. **루프가 끊기는 순간** — 실기까지 안 가면 차이를 잴 수 없고 차별점이 사라진다.
5. **인시를 파는 순간** — 파견 업으로 되돌아간다.
6. **에이전트 산출물을 검증 없이 넘기는 순간** — 지능의 규모(§10)가 빠르게 틀리는 능력이 된다.
7. **못 하는 것을 판다고 하는 순간** — 학습 정책 개발은 현재 [조사] 단계다.

## 10. 조직 — 규모의 단위가 바뀌었다

옛 전제는 **사람 수가 처리량을 정한다**였다. 지금 처리량을 정하는 것은 **지능의 규모**다.
사람 한 명과 여러 에이전트가 함께 일하고, 병목은 손이 아니라 **판단이 닿는 범위**에 있다.

| 사람이 정한다                         | 에이전트가 맡는다                   |
| ------------------------------------- | ----------------------------------- |
| 무엇을 재야 답이 나오는가 (질문 설계) | 조사 · 근거 수집 · 문서 대조        |
| 어떤 값을 믿을 수 있는가 (신뢰 등급)  | 자산 변환 · 환경 구성 · 반복 실행   |
| 무엇을 결론으로 넘길 것인가           | 계측 · 회귀 · 기록 · 재현 절차 정리 |
| 어디까지가 이 모델의 한계인가         | 전후 비교표 · 변경 이력 유지        |

**에이전트가 만든 것도 계측으로 확인되기 전에는 결론이 되지 않는다.**
고객에게 요구하는 기준(§6)을 자기 작업에 그대로 적용한다는 뜻이고,
이 조건이 빠지면 지능의 규모는 **빠르게 틀리는 능력**이 된다.

**늘어나지 않는 것도 있다** — 현장 상주, 여러 사이트 동시 실기 대응처럼 물리적 임장이
필요한 일은 이 구조로 커버되지 않는다(§3).
