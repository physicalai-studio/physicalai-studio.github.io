# 홈페이지 디자인 컨셉

## 1. Design Concept

전체 디자인은 **SpaceX에서 느껴지는 Aerospace Engineering / Industrial Minimalism / Cinematic Scale**을 주요 레퍼런스로 한다.

단, SpaceX 홈페이지를 그대로 복제하지 않는다.

우리가 가져올 것은 특정 UI가 아니라 다음과 같은 디자인 철학이다.

- 거대한 시스템을 다루는 기술회사라는 인상
- 극도로 절제된 Typography
- Black / White 중심의 강한 Contrast
- Full Screen Visual
- 실제 기술 이미지 중심
- 최소한의 UI
- 불필요한 장식 제거
- 짧고 강한 Copy
- 기술 자체를 Visual로 보여주는 구성

전체 사이트는 다음 느낌을 목표로 한다.

> **Engineering at Scale.**

> **Simulation Before Reality.**

> **Build the Physical World in Digital Space.**

---

# 2. Visual Identity

기본 컬러는 거의 무채색으로 구성한다.

### Primary

- Black
- Near Black
- White

### Secondary

- Dark Gray
- Light Gray

Accent Color는 필요한 경우에만 제한적으로 사용한다.

예:

- 상태 표시
- Simulation Data
- Robot Path
- Point Cloud
- CTA Hover

전체 화면에서 컬러가 주인공이 되지 않도록 한다.

**로봇, 시뮬레이션, 데이터 자체가 색을 가진다.**

---

# 3. Hero Section

첫 Hero는 매우 중요하다.

SpaceX 스타일의 **Full Viewport Hero** 형태로 구성한다.

화면 전체에 다음 중 하나를 배치한다.

- Isaac Sim Robot Simulation Video
- Robot Arm Motion
- AMR + Manipulator Simulation
- Humanoid Simulation
- Point Cloud Visualization
- Digital Twin Environment

Visual 위에 짧고 강한 메시지를 배치한다.

예:

### Option A

**PHYSICAL AI ENGINEERING**

Build in Simulation.
Validate Before Reality.

### Option B

**ROBOT SIMULATION**

From Digital World
to Physical Reality.

### Option C

**ENGINEERING THE PHYSICAL WORLD**

Simulation. Validation. Deployment.

---

CTA는 최소화한다.

Primary:

**VIEW OUR WORK**

Secondary:

**START A PROJECT**

버튼은 화려하게 만들지 않는다.

White Border / Transparent Background 기반으로 구성하고 Hover 시 White Fill 형태로 변화한다.

---

# 4. Homepage Experience

사용자가 사이트를 Scroll하면 하나의 기술 시연을 보는 느낌이어야 한다.

각 Section은 가능한 한 화면 하나를 크게 사용한다.

구조 예시:

```text
FULLSCREEN HERO

↓

ROBOT SIMULATION

↓

VIRTUAL COMMISSIONING

↓

DIGITAL TWIN

↓

PHYSICAL AI

↓

SELECTED PROJECTS

↓

ENGINEERING STACK

↓

START A PROJECT
```

여러 정보를 카드 형태로 한 화면에 빽빽하게 넣지 않는다.

**하나의 화면에서 하나의 메시지**를 전달한다.

---

# 5. Section Design

각 주요 서비스 Section은 Full Width Visual을 사용한다.

예:

```text
-------------------------------------------------

        ROBOT SIMULATION

     Validate before deployment.

     Reachability
     Collision
     Motion
     Cycle Time

                      [VIEW SERVICE]

-------------------------------------------------
```

배경에는 관련 Simulation 영상 또는 이미지를 사용한다.

텍스트는 화면 하단 또는 좌측에 배치한다.

---

# 6. Typography

Typography는 디자인의 핵심 요소다.

큰 제목은 매우 크고 단순하게 사용한다.

예:

```text
ROBOT
SIMULATION
```

또는

```text
PHYSICAL AI
```

Heading:

- Bold
- Uppercase 적극 활용
- 짧은 문장
- 넓은 여백

Body:

- 작은 크기
- 높은 가독성
- 지나치게 긴 설명 금지

페이지 첫 화면에서는 설명보다 **명사와 동사 중심의 문장**을 사용한다.

---

# 7. Copywriting Style

SpaceX 계열의 디자인에서는 Copy도 짧아야 한다.

잘못된 예:

> 당사는 NVIDIA Isaac Sim을 활용하여 다양한 산업용 로봇의 시뮬레이션 및 검증 서비스를 제공합니다.

권장:

> **SIMULATE BEFORE YOU BUILD.**

그리고 아래에 짧게:

> Robot motion, reachability and system behavior verified before deployment.

또는 한국어:

> **제작하기 전에 검증합니다.**

> 로봇의 움직임과 물리적 가능성을 가상환경에서 먼저 확인합니다.

---

# 8. Motion / Animation

Animation은 매우 절제해서 사용한다.

허용:

- Fade In
- Text Reveal
- Slow Scale
- Scroll-triggered Transition
- Background Video
- Image Parallax
- Section Transition

사용 금지:

- 지나친 Particle
- Neon Glow
- 화려한 Mouse Effect
- 불필요한 3D Object Rotation
- 지나친 Gradient Animation
- 의미 없는 Loading Animation

Animation은 화면을 꾸미기 위한 것이 아니라

**Scale과 Engineering Precision을 표현하기 위해 사용한다.**

---

# 9. Navigation

Navigation 역시 최소화한다.

Desktop:

```text
LOGO

SERVICES
PROJECTS
TECHNOLOGY
ABOUT

                         START A PROJECT
```

Header는 Transparent로 시작하고 Scroll 시 Dark Background로 변할 수 있다.

Mobile은 Hamburger Menu를 사용한다.

---

# 10. Projects

Project Page도 일반적인 카드 Grid보다 Case Study 중심으로 설계한다.

각 프로젝트는 큰 Visual을 사용한다.

예:

```text
AMR + MANIPULATOR

Material Handling Simulation

Isaac Sim / ROS2 / Digital Twin

                    VIEW PROJECT
```

Hover 시 이미지 또는 영상이 천천히 확대되는 정도의 효과만 사용한다.

---

# 11. Technology Section

Technology 역시 Logo Wall 형태로 만들지 않는다.

예:

### SIMULATION

NVIDIA Isaac Sim
OpenUSD
Isaac Lab

### ROBOTICS

ROS2
Robot Arm
AMR
Humanoid

### AI

Vision
Reinforcement Learning
Imitation Learning

가능하면 해당 기술이 실제 Simulation Visual 위에 Overlay되는 구조를 사용한다.

---

# 12. About

About 페이지 또한 Founder 사진과 긴 자기소개부터 보여주지 않는다.

먼저 Philosophy를 보여준다.

예:

# ENGINEERING BEFORE ASSUMPTION.

We validate robotic systems in simulation
before they become expensive physical problems.

그 아래에 Founder / Principal Engineer 소개를 배치한다.

---

# 13. Contact

Contact 페이지는 일반적인 문의 Form보다 프로젝트 시작 화면처럼 만든다.

큰 제목:

# START A PROJECT

Supporting:

Tell us what the robot needs to do.

그 아래:

- Name
- Company
- Email
- Project Type
- Project Description

Submit:

**SUBMIT PROJECT**

---

# 14. Image & Video Policy

이 홈페이지에서 가장 중요한 디자인 Asset은 실제 기술 이미지다.

우선순위:

1. 실제 Simulation Video
2. 실제 Robot Project Screenshot
3. Digital Twin
4. Robot Motion
5. Point Cloud
6. Engineering Visualization
7. CAD / Workspace Visualization

Stock Image는 가능한 한 사용하지 않는다.

특히 다음과 같은 이미지는 피한다.

- 악수하는 비즈니스맨
- Generic AI Brain
- 추상적인 회로 이미지
- 의미 없는 Robot Stock Photo
- Futuristic City
- 과도한 Cyberpunk Asset

**실제 엔지니어링 결과물이 곧 디자인이다.**

---

# 15. Responsive Principle

Desktop에서는 화면의 Scale을 적극적으로 사용한다.

Mobile에서는 영상과 Typography가 깨지지 않도록 우선한다.

Desktop의 Full Viewport 구조를 그대로 축소하지 말고 Mobile에서는 별도 Layout을 고려한다.

---

# 16. 핵심 디자인 원칙

전체 프로젝트에서 다음 원칙을 유지한다.

### ONE SCREEN, ONE MESSAGE

한 화면에는 하나의 주요 메시지만 존재한다.

### VISUAL FIRST

설명보다 실제 Simulation을 보여준다.

### ENGINEERING OVER DECORATION

장식보다 기술을 보여준다.

### SHORT COPY

긴 설명보다 강한 문장을 사용한다.

### SCALE

작은 스타트업 홈페이지가 아니라
큰 물리 시스템을 다루는 엔지니어링 회사의 분위기를 만든다.

---

# 17. 디자인 금지사항

다음 방향으로 구현하지 않는다.

- SaaS Dashboard 스타일
- 카드가 수십 개 있는 홈페이지
- 일반 IT 외주회사 느낌
- Purple / Blue Gradient 중심 AI Startup 디자인
- Cyberpunk
- Neon
- Glassmorphism 남용
- Generic AI 이미지
- 지나친 Icon 사용
- 과도한 Rounded Corner
- 귀여운 Illustration

특히 모든 요소를 Rounded Card 안에 넣지 않는다.

가능하면 **이미지 + Typography + Space**만으로 디자인한다.

---

# 18. 최종적인 브랜드 인상

사용자가 홈페이지를 보았을 때 다음 느낌을 받아야 한다.

> "여기는 웹 개발 회사가 아니다."

> "실제로 로봇과 물리 시스템을 다루는 엔지니어들이 만든 회사다."

> "설비를 만들기 전에 여기서 한번 검증해보고 싶다."

> "작은 조직이지만 기술적으로 깊어 보인다."

우리가 만드는 웹사이트는 화려한 광고물이 아니라,

**Physical AI와 Robotics Engineering을 보여주는 디지털 격납고**여야 한다.
