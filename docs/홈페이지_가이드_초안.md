# Physical AI Engineering Studio 홈페이지 개발 프로젝트

## 0. 프로젝트 개요

이 프로젝트는 로봇 시뮬레이션, 디지털트윈, Virtual Commissioning, Physical AI를 전문으로 하는 **1인 기술 기반 엔지니어링 스튜디오의 공식 웹사이트**를 개발하는 프로젝트다.

단순한 회사 소개 홈페이지가 아니라,

**고객의 로봇 문제 → 기술 검토 → 시뮬레이션 → 검증 → 실제 프로젝트 상담**

으로 연결되는 기술 중심의 비즈니스 플랫폼을 만드는 것이 목표다.

회사의 핵심 분야는 다음과 같다.

- NVIDIA Isaac Sim 기반 Robot Simulation
- ROS2 기반 Robot Integration
- Robot Arm / AMR / Humanoid Simulation
- Digital Twin
- Virtual Commissioning
- Reachability / Collision / Workspace Analysis
- Robot Motion & Cycle Time Verification
- Synthetic Data Generation
- Reinforcement Learning / Imitation Learning
- Physical AI Testbed
- Sim-to-Real 검증
- Agent 기반 엔지니어링 자동화

---

# 1. Project Goal

## 최종 프로젝트 목표

전문적인 로봇 엔지니어링 역량을 명확하게 전달하면서도 고객이 쉽게 이해할 수 있는 **고급 기술 회사 홈페이지**를 구축한다.

웹사이트 방문자가 약 30초 이내에 다음 세 가지를 이해할 수 있어야 한다.

1. 이 회사가 무엇을 하는가
2. 어떤 문제를 해결할 수 있는가
3. 프로젝트를 어떻게 의뢰할 수 있는가

사이트의 핵심 메시지는 다음과 같다.

> **Build in Simulation. Validate Before Reality.**

또는 향후 브랜드 전략에 따라 변경할 수 있도록 문구는 데이터 또는 별도 컴포넌트로 관리한다.

# 2. Business Positioning

이 회사를 일반적인 SI 업체 또는 단순 시뮬레이션 외주업체로 표현하지 않는다.

회사의 포지셔닝은 다음과 같다.

> **Physical AI Engineering Studio**

또는

> **Robot Simulation & Physical AI Engineering**

우리가 판매하는 것은 단순한 개발 인력이 아니라,

**로봇 시스템의 불확실성을 실제 제작 이전에 가상환경에서 발견하고 검증하는 엔지니어링 능력**

이다.

# 3. Core Value Proposition

홈페이지 전체에서 다음 가치가 자연스럽게 드러나야 한다.

### 3.1 Simulation First

실제 로봇과 설비를 제작하거나 설치하기 전에 가상환경에서 먼저 검증한다.

### 3.2 Engineering Validation

단순한 3D 영상이나 애니메이션을 제작하는 것이 아니라,

- Reachability
- Collision
- Robot Workspace
- Joint Limit
- Motion
- Cycle Time
- Sensor
- Control Interface

등을 실제 엔지니어링 관점에서 검증한다.

### 3.3 Physical AI

기존의 deterministic robotics와 AI 기반 robotics를 연결한다.

### 3.4 Sim-to-Real

시뮬레이션에서 끝나지 않고 실제 로봇 시스템으로 연결 가능한 구조를 만든다.

### 3.5 Agent-Native Engineering

AI Agent를 개발·테스트·문서화·분석 과정에 적극적으로 활용하여 소규모 조직에서도 높은 개발 생산성을 가진다.

단, 홈페이지에서는 "AI가 모든 것을 자동으로 한다"는 식의 과장 표현을 하지 않는다.

# 18. Development Principle for Agent

이 프로젝트를 한 번에 전부 개발하려고 하지 않는다.

각 Session마다 명확한 목표를 가지고 진행한다.

각 Session 시작 시 반드시 다음 작업을 수행한다.

1. 현재 코드 구조 확인
2. 현재 구현 상태 확인
3. 이번 Session 목표 정의
4. 수정 대상 파일 식별
5. 구현
6. Build / Lint / Test
7. 결과 정리
8. 다음 Session TODO 작성

기존 기능을 불필요하게 다시 작성하지 않는다.

# 23. 첫 번째 실행 명령

현재 Repository 전체 구조를 먼저 분석하라.

1. 현재 프로젝트 구조
2. 사용 중인 Framework / Library
3. 실행 방법
4. 주요 Page / Component
5. 현재 구현 상태
6. 재사용 가능한 코드
7. 제거 또는 개선이 필요한 부분
8. 홈페이지 목표와 현재 구조의 차이
