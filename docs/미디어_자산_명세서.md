> 근거: [디자인_컨셉.md](디자인_컨셉.md) §14 · [adr/0005-media-pipeline.md](adr/0005-media-pipeline.md)

## 1. 공통 촬영 규칙

| 항목    | 규격                                                                                         |
| ------- | -------------------------------------------------------------------------------------------- |
| 해상도  | 3840×2160 또는 2560×1440 로 캡처 → 배포용은 1920×1080 로 다운스케일                          |
| 프레임  | 30fps 또는 60fps. 카메라 이동은 **느리고 일정하게** — 급격한 팬·줌 금지                      |
| 길이    | 히어로 루프 8–12초. 섹션용 6–10초. **시작과 끝 프레임이 이어지도록** 구성해 루프 이음새 제거 |
| 오디오  | **없음.** 오디오 트랙 자체를 제거한다(자동재생 정책·용량 양쪽에 유리)                        |
| UI 요소 | Isaac Sim 의 뷰포트 UI · 기즈모 · 커서를 **화면에서 제거**한 상태로 캡처                     |
| 배경    | 어두운 배경 우선. 사이트 배경(`#08090a`)과 이질감이 적어야 한다                              |
| 여백    | 화면 중앙~하단에 **텍스트가 얹힐 여백**을 남긴다(히어로는 하단 40% 를 비운다)                |
| 색      | 로봇·궤적·포인트클라우드 자체의 색만 사용. 인위적 네온·글로우 효과 금지                      |

## 2. 인코딩 규격

| 용도          | 포맷                           | 목표 용량 | 비고                            |
| ------------- | ------------------------------ | --------- | ------------------------------- |
| 히어로 영상   | H.264 MP4 + WebM(VP9 또는 AV1) | ≤ 4MB     | 2종 모두 제작 — 브라우저 폴백용 |
| 섹션 영상     | 위와 동일                      | ≤ 2.5MB   |                                 |
| 포스터 이미지 | WebP(+JPEG 폴백)               | ≤ 250KB   | **모든 영상에 필수**            |
| 정지 스크린샷 | WebP(+JPEG 폴백)               | ≤ 400KB   | 1920px 폭 기준                  |

참고 인코딩 명령(예시):

```bash
# 오디오 제거 + 1080p + H.264
ffmpeg -i input.mp4 -an -vf "scale=1920:-2" -c:v libx264 -crf 26 -preset slow -movflags +faststart hero.mp4
# WebM(VP9)
ffmpeg -i input.mp4 -an -vf "scale=1920:-2" -c:v libvpx-vp9 -crf 34 -b:v 0 hero.webm
# 포스터 (1.5초 지점 프레임)
ffmpeg -ss 1.5 -i input.mp4 -frames:v 1 -vf "scale=1920:-2" -q:v 80 hero-poster.webp
```

범례: 🟢 절차적 생성(자체·라이선스 무관) · 🟡 자체 제작 정지 이미지로 임시 충족(영상으로 교체 예정) · 🔴 제3자 자산(교체 필요) · ⚪ 미준비

> **`home-hero` 영상을 가장 먼저 확보한다.** 지금은 정지 이미지가 들어가 있어 사이트가 성립하지만, 첫 화면은 영상일 때 인상이 크게 달라진다.
>
> **제3자 자산은 3곳**(`service-vc` · `service-twin` · `technology-actuator`)이며 전부 **초안**이다. 자체 자산이 준비되는 대로 교체한다(debt-006).

### 현재 사용 중인 제3자 자산 (2026-08-13)

전부 Wikimedia Commons 출처이며, 사이트 화면에도 권리자 · 라이선스 · 편집 사실이 표기된다.

| 슬롯                  | 자산                                | 라이선스     | 권리자            | 가공                   |
| --------------------- | ----------------------------------- | ------------ | ----------------- | ---------------------- |
| `service-vc`          | 의료기기 제조 로봇 셀               | CC0 1.0      | Lexington Medical | 리사이즈 · 초록 듀오톤 |
| `service-twin`        | Ouster OS1-64 LiDAR 포인트 클라우드 | CC BY 4.0    | Daniel L. Lu      | 리사이즈 · 초록 듀오톤 |
| `technology-actuator` | 하모닉 드라이브(파동 기어) 내부     | CC BY-SA 4.0 | wdwd              | 크롭 · 초록 듀오톤     |

**반려한 후보**(기록 — 같은 판단을 반복하지 않기 위해):

- Ignition/Gazebo 시뮬레이터 스크린샷 — 수중 드론(LRAUV) 장면 + 밝은 청록 배경 + 툴바 UI 노출. 디자인 컨셉 §14(뷰포트 UI 제거) 위반
- Universal Robots UR16e 렌더 — 누끼 경계에 검정·노랑 아티팩트가 남아 품질 미달

**CC BY / CC BY-SA 준수 사항**: 저작자 표시 · 라이선스 표시 · **변경 사실 표시** 3가지가 모두 필요하다. 자산을 크롭하거나 톤을 조정했다면 매니페스트의 `credit.isModified` 를 `true` 로 두어야 화면에 "편집됨"이 표기된다.

## 4. 공개 가능 여부 확인 (필수)

모든 자산은 매니페스트에 **공개 근거**를 함께 기록한다. 근거가 없으면 코드가 게시하지 않는다.

| 값                | 의미                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| `self-produced`   | 자체 제작 자산. 제약 없음                                                |
| `client-approved` | 고객사가 공개에 동의함                                                   |
| `anonymized`      | 고객 식별 정보를 제거해 공개 가능한 상태                                 |
| `licensed`        | 제3자 자산. **`credit`(권리자 · 라이선스 · 출처 URL) 필수**, 화면에 표기 |
| `pending`         | 미확인 — **게시되지 않음**                                               |

실제 프로젝트에서 나온 화면은 설비 배치·제품 형상만으로도 고객사가 식별될 수 있다. 자체 제작 씬으로 재구성하는 편이 안전한 경우가 많다.

### 제3자 이미지에 대한 원칙

라이선스가 깨끗해도(CC0 등) 제3자 이미지는 **최소한으로만** 쓴다. 이유는 저작권이 아니라 **브랜드**다.

- 디자인 컨셉 §14 는 "실제 엔지니어링 결과물이 곧 디자인"이라고 못박는다. 남의 설비 사진은 이 주장을 약화시킨다.
- 특히 **Projects(케이스 스터디) 슬롯에는 제3자 이미지를 절대 넣지 않는다.** 그 자리는 "우리가 한 일"을 주장하는 자리이고, 남의 사진은 실적 허위 표시가 된다.
- 제3자 이미지를 쓴다면 서비스 설명의 **맥락 이미지**까지만 허용하고, 화면에 출처를 표기하며, 자체 자산으로 교체할 부채를 등록한다.

## 4-1. 톤 그레이딩 — 초록 듀오톤 (2026-08-13 도입)

사이트 배경이 near-black(`#08090a`)이므로, 배포용 이미지는 **초록 듀오톤**으로 통일한다.
원본의 색(시뮬레이터 청록 UI, 포인트 클라우드 마젠타 등)이 제각각이면 화면이 흩어지기 때문이다.

| 단계 | 처리                                                                        |
| ---- | --------------------------------------------------------------------------- |
| 1    | 휘도만 남긴다(grayscale) — 원본 색상 제거                                   |
| 2    | `autocontrast(cutoff=1)` 로 대비 정규화                                     |
| 3    | **감마 > 1** 로 중간톤을 눌러 검정 배경에 가라앉힌다 (밝은 원본일수록 크게) |
| 4    | 게인으로 최종 노출 조정                                                     |
| 5    | 듀오톤 매핑 — 그림자 `#030907` · 중간 `#11422d` · 하이라이트 `#89f7ba`      |

- 실행: `python3 scripts/build-media.py` — `image/` 원본에서 `public/media/` 를 **전부 재생성**한다.
- **배경 광장(光場) 2종은 예외**: `python3 scripts/gen-fields.py` 가 **수식으로 생성**한다(원본 사진 없음).
  - `home-hero-field` — 겹친 고리(토로이달 발광체)
  - `home-contact-field` — 두 파동원의 간섭 무늬(쌍곡선 프린지)
    두 이미지는 같은 초록 램프·그레인을 공유하고 형상만 다르다. 반경·간격·감마가 상수로 노출되어 있다.
- 파라미터(크롭·게인·감마)는 그 스크립트의 `JOBS` 표에 이미지별로 들어 있다.
- **원본은 절대 덮어쓰지 않는다.** 톤을 다시 잡고 싶으면 스크립트 값만 바꿔 재실행한다.
- 중성(무채색) 버전은 `image/_neutral/` 에 백업해 두었다 — 초록 톤을 되돌릴 때 쓴다.
- UI 액센트(`--color-accent`)는 듀오톤 하이라이트와 같은 계열(`#74eeae`)로 맞춘다.

> **디자인 컨셉과의 관계**: §2 는 "컬러가 주인공이 되지 않게" 하라고 하고 §17 은 네온·과채도를 금지한다.
> 초록 듀오톤은 **단일 색상 + 낮은 채도 + 어두운 노출**로 이 조건을 지키는 범위 안에서 적용한다.
> 하이라이트 면적이 넓어지면 §17 위반으로 넘어가므로, 감마를 낮추는 방향(밝게)으로 조정하지 않는다.

## 5. 반영 절차

1. 위 규격대로 캡처·인코딩한다.
2. 자산을 외부 스토리지에 업로드한다(저장소에 커밋하지 않는다).
3. 정지 이미지는 `image/` 에 원본을 두고 `scripts/build-media.py` 의 `JOBS` 에 항목을 추가한다.
4. `src/content/media.ts` 의 해당 슬롯을 교체한다:

   ```ts
   "home-hero": {
     kind: "video",
     sources: [
       { src: "https://<스토리지>/hero.webm", type: "video/webm" },
       { src: "https://<스토리지>/hero.mp4", type: "video/mp4" },
     ],
     poster: "https://<스토리지>/hero-poster.webp",
     alt: "Isaac Sim 에서 로봇팔이 소재를 공급하는 시뮬레이션",
     clearance: "self-produced",
   },
   ```

5. `npm run verify` 로 검증한다. 스키마 위반이면 빌드가 실패한다.
