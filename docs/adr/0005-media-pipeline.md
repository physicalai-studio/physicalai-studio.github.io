# ADR-0005 — 미디어 자산 파이프라인

## Status

Accepted (2026-08-13)

## Context

디자인 컨셉의 핵심 자산은 실제 시뮬레이션 영상과 스크린샷이다. 그런데 (1) 현재 보유 자산이 0이고, (2) 영상 원본을 git 에 커밋하면 저장소가 급격히 무거워지며, (3) 실 프로젝트 캡처는 고객사 자산일 수 있어 공개 가능 여부 확인이 필요하다.

## Decision

**매니페스트 기반 placeholder-first 구조**를 채택한다.

- `src/content/media.ts` 가 슬롯 ID → 자산을 매핑한다. 페이지는 슬롯 ID 만 참조한다.
- 자산 종류는 `placeholder` · `image` · `video` 세 가지이며, `image`/`video` 는 **공개 근거(`clearance`)** 필드를 반드시 가진다.
- `MediaSlot` 컴포넌트가 폴백을 한 지점에서 처리한다: 공개 근거 미확인 → 플레이스홀더, 모션 축소 설정 → 포스터 이미지, 그 외 → 영상.
- **영상 원본을 저장소에 커밋하지 않는다.** `.gitignore` 에 `*.mp4`·`*.webm`·`*.mov`·`*.mkv` 를 등록했다. 외부 스토리지/CDN 의 URL 만 매니페스트에 둔다.
- 촬영·인코딩 규격은 `docs/미디어_자산_명세서.md` 를 따른다.

## Consequences

- 자산이 하나도 없어도 전 페이지가 렌더되고 배포된다. 캡처 작업이 코드 개발을 막지 않는다.
- 자산 교체가 `media.ts` 수정만으로 끝난다. 컴포넌트를 건드리지 않는다.
- 공개 근거가 `pending` 인 자산은 코드 경로상 게시되지 않는다 — NDA 위반 위험을 구조로 막는다.
- 외부 스토리지 선택은 아직 미정이다(Cloudflare R2 등).

## Rollback

가역. 자산을 저장소에 직접 두는 방식으로 되돌리려면 매니페스트의 URL 을 로컬 경로로 바꾸면 된다. 다만 그 경우 저장소 용량과 호스트 대역폭 제한을 다시 검토해야 한다.

## 개정 2026-08-13 — 제3자 자산 허용 범위

**변경 배경**: 자체 자산이 거의 없는 상태에서 사이트 초안의 시각적 완성도를 확인해야 했다. 사용자 요청으로 자유 라이선스 제3자 이미지를 초안 자산으로 도입한다.

**추가 결정**:

- `clearance` 에 `licensed` 를 추가한다. 이 값을 쓰는 자산은 `credit`(권리자 · 라이선스 · 출처 URL)이 **스키마 수준에서 필수**이며, 없으면 빌드가 실패한다.
- CC BY / CC BY-SA 는 저작자 · 라이선스 · **변경 사실** 표시를 요구하므로 `credit.isModified` 를 두고 화면에 "편집됨"을 표기한다.
- **Projects(케이스 스터디) 슬롯에는 제3자 자산을 쓰지 않는다.** 그 자리는 자사 실적을 주장하는 자리이며, 제3자 이미지는 허위 표시가 된다. 허용 범위는 서비스 · 기술 · 회사 소개의 **맥락 이미지**까지다.
- 정지 이미지는 사전 최적화 후 `public/media/` 에 커밋한다(영상 제외 규칙은 그대로 유지).

**결과**: 초안 단계에서 전 페이지의 시각 구성을 확인할 수 있다. 대신 자체 자산으로 교체할 부채가 남는다(debt-006).
