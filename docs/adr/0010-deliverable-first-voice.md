# ADR-0010 — 경계 선언이 아니라 제공물로 말한다

## Status

Accepted (2026-08-14)

ADR-0008 의 §1-1(역할 경계)을 **개정**한다. 경계의 내용은 유지하되 서술 형태를 바꾸므로
ADR-0008 을 `Superseded` 로 두지 않는다.

## Context

사이트 문구가 여섯 곳에서 같은 형태를 쓰고 있었다 — **누가 무엇을 맡는지의 경계 선언.**

| 위치           | 문구                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| 홈 히어로      | "We Build the Simulation. / You Build the Robot."                                  |
| About 철학문   | "로봇을 만드는 것은 고객입니다. 우리가 만드는 것은 그 개발이 올라탈 자리 —"        |
| 홈 02 Services | "고객의 개발을 **대신하지 않고**, 그 개발이 이 위에서 돌게 만듭니다."              |
| 홈 04 Projects | "로봇을 **대신 만든 기록이 아니라**, 그 개발이 무엇 위에서 돌았는지의 기록입니다." |
| 홈 06 Why      | "도구를 다루는 것과 로봇을 아는 것은 **다른 일**입니다"                            |
| Founder 소개   | "로봇을 **직접 만들지는 않습니다** —"                                              |

사용자 지적(2026-08-14): 이 태도가 아니라 **고객이 필요한 가상 에셋을 빠르게 구축해 주는 것**이며,
"니 꺼 내 꺼"를 나누는 형태가 아니라 **어떤 것을 빠르게 구축해 주고 어떤 work 를 하는지**의
형태로 써야 한다.

타당한 지적이다. 경계 선언은 내부적으로는 사업이 개발 대행·인시 판매로 미끄러지는 것을 막는
장치지만(§9-3), 고객이 읽으면 **"안 해 주는 일 목록"**이 된다. 방문자가 30초 안에 받아야 할 것은
"이 회사가 무엇을 안 하는가"가 아니라 "여기서 무엇을 받는가"다.

## Decision

**사이트의 모든 문구를 제공물 중심으로 쓴다.** 부정문("~하지 않습니다", "~가 아니라")으로
경계를 선언하지 않는다. 경계는 산출물 목록이 스스로 말하게 한다 — 목록에 로봇도 제어
소프트웨어도 없다는 사실이 선언보다 강하다.

- **히어로를 `SIMULATION ASSETS, / BUILT FAST.` 로 교체**한다(사용자 결정). 기간 숫자는 걸지
  않는다 — 근거 없는 수치를 쓰지 않는 것이 §2 의 규칙이므로, 속도 주장은 바로 아래
  `site.description` 이 **무엇을 세워 주는지**로 뒷받침한다.
- 나머지 다섯 곳을 같은 톤으로 다시 쓴다.
- **`docs/사업_정의.md` §1-1 을 "역할 경계 — 누가 무엇을 하는가"에서 "제공물 — 무엇을 세워
  넘기는가"로 개정**한다. 이 문서는 "홈페이지의 모든 문구는 여기서 파생된다"고 선언한 SSOT 이므로,
  문서를 두면 다음 세션이 경계 톤을 다시 살려 낸다.
- 고객에게서 **입력으로 받아야 하는 것**(작업 시나리오)은 계속 명시한다. 이것은 경계가 아니라
  **성립 조건**이다 — 무엇을 어떤 순서로 하는지를 모르면 세울 대상 자체가 정해지지 않는다.
- 콘텐츠 파일 주석도 함께 고친다(`services.ts` · `contact.ts` · `site.ts` · `home.ts`).
  주석이 다음 세션의 작성 지침이므로, 주석만 남으면 문구가 되돌아온다.

## Consequences

- 문구가 **방어에서 제안으로** 바뀐다. 읽는 사람이 받는 첫인상이 "무엇을 안 하는 곳"에서
  "무엇을 빨리 세워 주는 곳"이 된다.
- **"FAST" 가 근거 없이 뜨는 위험이 생긴다.** 기간 숫자를 걸지 않아 거짓 주장은 아니지만,
  흔한 카피로 읽힐 여지는 남는다. 실제 구축 소요를 케이스별로 재서 Projects 의 `metrics` 에
  넣을 수 있게 되면 그때 숫자로 대체하는 것이 다음 단계다 — **현재는 근거 미확보 상태**이므로
  숫자를 쓰지 않는다.
- 개발 대행 문의가 늘 수 있다. 경계를 큰 소리로 선언하지 않기 때문이다. 대신
  `services.ts` 의 `deliverables` 목록과 사업_정의 §2("하지 않는 일")가 견적 단계에서 그 역할을
  진다 — 즉 **경계를 마케팅 문구에서 견적 기준으로 옮긴 것**이지 없앤 것이 아니다.
- ADR-0009 가 세운 다섯 문(HOW WE WORK)은 영향받지 않는다. 그 문구들은 원래 제공물·방법 서술이었다.

## Rollback

가역. 변경은 `src/content/`(home · site · company · services · contact)와 `docs/사업_정의.md` §1-1 에
한정되며 렌더 코드는 건드리지 않았다. 되돌리려면 이 ADR 을 `Superseded` 로 표시하고 §1-1 의
경계 표를 복원한다. 다만 되돌리는 것은 기술 판단이 아니라 사업 판단이다.
