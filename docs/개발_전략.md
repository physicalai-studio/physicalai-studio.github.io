## 2. 가이드가 다루지 않은 항목 (전략에서 보강)

가이드·디자인 문서는 **무엇을 만들지**는 충실하나, 다음은 비어 있고 전부 착수 전에 결정되어야 한다.

| 항목                         | 왜 중요한가                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------- |
| **브랜드명·도메인**          | 로고·`<title>`·OG(Open Graph) 이미지·이메일·JSON-LD 전부의 입력. 미확정 시 전 페이지 재작업 |
| **호스팅·배포 대상**         | 정적/서버 렌더링 선택을 결정 → `next.config` 및 폼 처리 방식이 갈림                         |
| **미디어 자산 파이프라인**   | 디자인 컨셉의 핵심 자산이 **영상**인데, 영상은 git 에 넣으면 안 된다. 별도 전략 필수        |
| **자산 공개 가능 여부(NDA)** | 실 프로젝트 캡처는 대부분 고객사 자산. 공개 범위 확인 없이 게시하면 계약 위반 위험          |
| **언어(로케일) 정책**        | 나중에 넣으면 라우팅 구조 변경 = 전면 재작업                                                |
| **개인정보 처리**            | 문의 폼은 개인정보 수집. 동의 절차·처리방침 페이지 없이 운영 불가                           |
| **성능 예산**                | "Full Viewport 영상 + 한글 웹폰트" 조합은 방치하면 LCP(Largest Contentful Paint) 붕괴 확정  |
| **저장소 공개 여부**         | 현재 private. 호스팅 선택과 연동                                                            |

## 3. 전략 기본 방침

1. **결정 우선, 코드 나중.** §7 미결 결정 4건이 Session 01 산출물의 형태를 바꾼다. 확정 후 착수한다.
2. **콘텐츠와 UI 완전 분리.** 모든 문구·서비스·프로젝트·기술 스택은 `src/content/` 데이터 모듈에만 존재한다. 컴포넌트에 문자열 하드코딩 금지 → 문구 교체·로케일 추가·CMS(Content Management System) 이전이 UI 수정 없이 가능(가이드 §15·§16 요구사항의 이행 수단).
3. **자산 placeholder-first.** 실제 시뮬레이션 영상이 없어도 전 구간을 개발·배포할 수 있어야 한다. 자산은 매니페스트로 주입하고, 미준비 슬롯은 정적 플레이스홀더로 폴백한다(가이드 §14 요구).
4. **완료 조건은 검증 가능해야 한다.** 각 세션 종료 조건을 `build 성공 / lint 0 / tsc 0 / 라우트 스모크 통과 / 성능 예산 충족`처럼 기계로 판정 가능한 형태로만 정의한다.
5. **한 세션 = 한 커밋 단위.** git_workflow SOP §1(작업 단위 = 커밋 단위, 명시 staging)을 그대로 따른다.

## 4. 권장 Architecture

### 4.1 스택

| 층        | 선택                                                                                   | 근거                                                                                                                |
| --------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Framework | **Next.js (App Router) + TypeScript strict**                                           | 가이드 §15 권장. 라우팅·메타데이터·이미지 최적화가 SEO(Search Engine Optimization) 요구(§10 Session 10)를 기본 제공 |
| Styling   | **Tailwind CSS + 디자인 토큰**                                                         | 가이드 §15. 단 유틸리티 남발 금지 — 색·간격·타이포는 토큰으로만                                                     |
| Animation | **CSS transition + IntersectionObserver 우선**, 부족할 때만 Framer Motion              | 디자인 컨셉 §8이 허용한 효과(Fade In / Text Reveal / Slow Scale)는 대부분 CSS로 충분. 의존성 최소화(가이드 §16)     |
| Content   | `src/content/*.ts` + **zod 스키마 검증**, 장문 케이스 스터디는 MDX                     | 데이터 오류를 빌드 타임에 잡는다                                                                                    |
| 검증      | ESLint + Prettier + `tsc --noEmit` + Vitest(콘텐츠 스키마) + Playwright(라우트 스모크) | coding SOP §5 "전체 회귀" 이행                                                                                      |

**의도적으로 채택하지 않는 것**: CMS, 상태관리 라이브러리, UI 킷(shadcn 등 카드 중심 프리셋 — 디자인 컨셉 §17 "Rounded Card 금지"와 충돌), 3D 렌더 라이브러리(three.js — 가이드 §21 "의미 없는 3D Animation" 금지).

### 4.3 디자인 시스템 토큰 (디자인 컨셉 §2·§6의 코드화)

- **색**: `--bg`(near black) / `--fg`(white) / `--muted`(gray 2단) / `--accent` 1개. 액센트는 상태 표시·CTA(Call To Action) hover·데이터 시각화에만 허용. 그라디언트 토큰 없음(§17 금지).
- **타이포**: 헤딩 = 영문 대문자, `clamp()` 기반 유동 스케일(뷰포트 대응 "SCALE" 표현). 본문 = 작은 크기·높은 행간.
- **폰트 전략(성능 직결)**: 한글 웹폰트는 용량이 크다. 헤딩(영문)은 서브셋 가변 폰트, 한글 본문은 **Pretendard 서브셋 woff2 + `font-display: swap` + 폴백 메트릭 정렬**. 총 폰트 예산 ≤ 150KB.
- **모서리**: `border-radius` 기본 0. 라운드 사용은 예외로 ADR 기록(§17 "과도한 Rounded Corner" 금지의 강제 수단).
- **모션**: `prefers-reduced-motion` 존중 필수. 이 설정에서는 영상 자동재생·리빌 전부 비활성.

### 4.4 미디어 파이프라인 (최고 위험 항목)

| 규칙      | 내용                                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 저장 위치 | **원본 영상을 git 에 커밋하지 않는다.** 외부 스토리지/CDN(Content Delivery Network)에 두고 `content/media.ts` 가 URL 만 참조. `.gitignore` 에 `*.mp4` 등 추가 |
| 인코딩    | 히어로 루프 = 무음·8~12초·H.264 MP4 + WebM(AV1) 2종, 목표 ≤ 4MB. 포스터 이미지 필수                                                                           |
| 모바일    | 디자인 컨셉 §15에 따라 모바일은 영상 대신 **포스터 정지 이미지** 기본(데이터 절약·디코딩 부하 회피)                                                           |
| 폴백      | `MediaSlot` 컴포넌트가 (영상 → 포스터 → 플레이스홀더) 3단 폴백을 단일 지점에서 처리. 자산 미준비가 개발을 막지 않는다                                         |
| 캡처 목록 | Phase 0에서 "필요 자산 명세서"를 작성해 사용자에게 전달 → 캡처 작업은 코드 개발과 **병렬 진행**                                                               |
| 공개 검증 | 각 자산에 `공개 가능 근거`(자체 제작 / 고객 승인 / 익명화 완료)를 매니페스트에 명시. 미확인 자산은 게시 금지                                                  |

## 6. 세션 로드맵

가이드 §19의 10세션을 유지하되, 누락된 **Phase 0(결정·기반)** 과 **배포·법적 요건**을 보강하고 선행 의존을 명시했다.

### ✅ Phase 0 — 결정과 기반 _(완료 2026-08-13)_

- **P0-1** ADR 6건 기록(`docs/adr/`): 호스팅 · 렌더링 모드 · 로케일 · 폼 수신 · 미디어 파이프라인 · 의존성
- **P0-2** 하네스 번들 4종 설치(coding·git_workflow·debt·code_review), CI 에 검사 연결
- **P0-3** [미디어 자산 명세서](미디어_자산_명세서.md) 작성 → **사용자 캡처 track 착수 가능**
- 검증: `adr-fields.sh` 통과, 부채 registry 5건 등록

### ✅ Phase 1 — Foundation _(완료 2026-08-13, 가이드 Session 01)_

- Next.js 16 + TS + Tailwind 4 구성, 디자인 토큰, `Header`/`Footer`/`Container`/`Section`/`Reveal`/`MediaSlot`, 6개 라우트, zod 콘텐츠 계층, sitemap·robots, 404, CI 파이프라인
- 검증 결과: 정적 export 12개 HTML 생성 · 6개 라우트 + 프로젝트 상세 전부 200 · 없는 경로 404 · lint 0 · tsc 0 · 테스트 10건 통과
- 산출물 인벤토리: [code_inventory/2026-08-13.md](code_inventory/2026-08-13.md)

### Phase 2 — Home 핵심 _(다음, Session 02~04)_

- **S02 Hero**: Full Viewport, 메인/서포팅 카피, CTA 2종(테두리 → hover fill), `MediaSlot` 적용
- **S03 Core Services**: 5개 서비스를 "고객이 얻는 결과" 중심으로. 카드 그리드 아님 — 풀폭 섹션 연속
- **S04 Workflow**: Problem → Model → Simulate → Validate → Deploy 시각화(SVG + 스크롤 리빌, 3D 금지)
- 완료 조건: 30초 안에 가이드 §20 Q1·Q2에 답이 되는지 자체 점검 + 모바일 레이아웃 무붕괴

### Phase 3 — 신뢰 확보 _(Session 05~07)_

- **S05 Projects**: Case Study 구조(Problem/Environment/Simulation/Verification/Result) + `[slug]` 상세. 데이터 기반 추가·삭제
- **S06 Technology**: 나열 금지 — 기술별 "프로젝트에서의 역할" 서술
- **S07 About**: Philosophy 우선, Founder 소개는 그 아래(디자인 컨셉 §12)
- 완료 조건: 가이드 §20 Q3·Q4 충족, 샘플 프로젝트 ≥ 3건

### Phase 4 — 전환 _(Session 08)_

- Contact 폼 + zod 검증 + `submitInquiry()` 어댑터 인터페이스(구현체는 §7 D4 결정 따름)
- 스팸 대응(honeypot + rate limit), **개인정보 수집·이용 동의 체크 + 개인정보처리방침 페이지**, 성공/실패 상태 UI
- 완료 조건: 실제 수신 경로로 테스트 문의 1건 도달 확인

### Phase 5 — 마감과 출시 _(Session 09~10 + 배포)_

- 타이포·간격·반응형·hover·transition 정리, 접근성, SEO 메타·OG 이미지·sitemap·robots·JSON-LD, 이미지/영상 최적화
- 도메인 연결, 배포 파이프라인, 서치콘솔·네이버 서치어드바이저 등록, 404 페이지
- 완료 조건: §5 품질 게이트 전 항목 통과 + 실도메인 접속

**병렬 track (코드와 무관, 즉시 착수 가능)**: 브랜드 확정 → 시뮬레이션 영상·스크린샷 캡처 → 프로젝트 케이스 원고 작성. 이 track이 Phase 2·3의 실질 품질을 좌우하므로 가장 먼저 시작하는 편이 좋다.

### 세션 운영 규칙 (가이드 §18·§22 이행)

매 세션은 `현재 구조 확인 → 목표 정의 → 대상 파일 식별 → 구현 → build/lint/test → 결과 정리 → 다음 TODO` 순으로 진행하고, 종료 시 가이드 §22의 `[Session Result]` 포맷으로 보고한다.
