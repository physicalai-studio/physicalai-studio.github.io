## 2. ⚠ GitHub Pages 로 가기 전 반드시 확인할 것

**GitHub Pages 는 무료 요금제에서 public 저장소만 호스팅한다.** 그런데 이 저장소를 public 으로 바꾸면 **커밋 이력 전체**가 공개된다. 파일을 지워도 이전 커밋에 남는다.

### 공개하면 노출되는 것

| 파일                         | 내용                                                                      |
| ---------------------------- | ------------------------------------------------------------------------- |
| `docs/research/역량_지도.md` | 재직 회사명 · 고객사명 · 사내 장비명 (실명 다수) — **이력에서 제거 대상** |

이 파일은 "사이트에 게시하지 않는다"를 전제로 작성했다. 그 전제는 **웹사이트 기준**이었고, **저장소 공개는 별개의 노출 경로**다.

### 그래서 공개 전환은 아래 중 하나를 먼저 해결해야 한다

1. **역량_지도에서 실명을 전부 제거**하고, **커밋 이력에서도 제거**한다 (`git filter-repo` 등으로 이력 재작성 → force push. 파괴적 작업이라 명시 승인 필요).
2. 또는 그 문서를 **저장소 밖**(로컬 `my_docs/` 등)으로 옮기고 같은 이력 정리를 한다.
3. 또는 **공개하지 않는다** → §3 의 다른 선택지로 간다.

> 이력 재작성 없이 파일만 지우고 공개하면 **아무 효과가 없다.**

## 3. 선택지

| 방법                                    | 저장소       | 비용                 | 지금 가능?                                  |
| --------------------------------------- | ------------ | -------------------- | ------------------------------------------- |
| **A. Cloudflare Pages** (ADR-0001 결정) | private 유지 | 무료(상업 이용 가능) | 계정 연결만 하면 됨 — **권장**              |
| **B. GitHub Pages + 저장소 public**     | public       | 무료                 | §2 해결 후 가능                             |
| **C. GitHub Pages + GitHub Pro**        | private      | 유료(월 구독)        | 구독하면 즉시 가능                          |
| **D. 산출물만 별도 public 저장소로**    | private      | 무료                 | 소스는 비공개, `out/` 만 공개 저장소로 push |

**A 가 원래 결정이고 가장 깔끔하다.** 소스가 비공개로 남고, 무료이며, 상업적 이용이 허용된다.

### A. Cloudflare Pages 설정 (사용자 작업)

1. Cloudflare 계정 → Workers & Pages → Create → Pages → Connect to Git
2. `DDUGGOGI/homepage` 선택 (private 저장소도 연결된다)
3. 빌드 설정

   | 항목             | 값              |
   | ---------------- | --------------- |
   | Framework preset | None            |
   | Build command    | `npm run build` |
   | Output directory | `out`           |
   | Node version     | `22`            |

4. 환경 변수: `NEXT_PUBLIC_SITE_URL` = 배포 도메인 (예: `https://homepage.pages.dev`)
   - `NEXT_PUBLIC_BASE_PATH` 는 **설정하지 않는다** (루트 도메인 배포이므로)

### B. GitHub Pages 설정 (§2 해결 후)

1. 저장소 Settings → General → Danger Zone → Change visibility → Public
2. Settings → Pages → Source → **GitHub Actions**
3. `main` 에 push 하면 `.github/workflows/deploy-pages.yml` 이 자동 실행
4. 주소: `https://dduggogi.github.io/homepage/`

워크플로가 `NEXT_PUBLIC_BASE_PATH` 와 `NEXT_PUBLIC_SITE_URL` 을 Pages 설정에서 자동으로 읽어 넣는다.

## 4. 하위 경로 배포 대응 (이미 구현됨)

GitHub Pages 프로젝트 사이트는 `/<repo>` 하위에 놓인다. 이 때문에 필요한 처리를 코드에 넣어 두었다.

| 문제                                                      | 처리                                                            |
| --------------------------------------------------------- | --------------------------------------------------------------- |
| `next/link`·`next/image` 외의 **원시 `<img src>`** 미보정 | `withBasePath()` 를 `MediaSlot` 이 통과 (`src/lib/basePath.ts`) |
| `new URL("/x", base)` 가 base 의 하위 경로를 날림         | `absoluteUrl()` 로 문자열 결합. 회귀 테스트 있음                |
| `_next` 디렉토리가 Jekyll 에 걸러짐                       | `public/.nojekyll`                                              |

**루트 도메인 배포(A안)에서는 이 값들이 전부 비어 있어 아무 영향이 없다.**

로컬에서 하위 경로 배포를 확인하려면:

```bash
NEXT_PUBLIC_BASE_PATH=/homepage NEXT_PUBLIC_SITE_URL=https://dduggogi.github.io/homepage npm run build
npx serve out -l 4321   # http://localhost:4321/homepage/ 로 접속
```
