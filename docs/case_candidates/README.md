가치가 크지만 공개 전 근거 보강이 필요하다.

## 현재 Case Study 틀에 대한 통과 기준

- 구매자 요약: 고객 유형, 착수 전 문제, 의사결정, 기간, 제공물, 활용 결과, 사업 효과
- 기술 본문: Problem, Environment, Simulation, Verification, Result
- Architecture: 3~5개 계층과 계측 결과가 모델로 돌아오는 feedback
- Metrics: 공개 근거가 있는 계측값 최소 3개
- Engineering Notes: 재사용 가능한 설계 판단 최소 2개
- 미디어: 공개 권한이 확인된 자체 제작·익명화 이미지 또는 영상

## 공개 전 공통 확인사항

1. 원본 README에 있는 고객사·기관명과 장비 고유명은 홈페이지에서 삭제한다.
2. `$150K`, `$100K` 같은 금액과 절감률은 계산표 또는 계약·프로젝트 기록으로 다시 확인한다.
3. `95%+ 정합성`처럼 여러 항목을 하나의 비율로 합친 값은 산식과 표본을 명시한다.
4. GitHub user-attachments 이미지는 소유권과 고객 공개 승인을 확인한 뒤 로컬 자산으로 이전한다.
5. 실제 현장 사진은 로고, 작업자 얼굴, 레이아웃, 설비 번호를 제거하고 익명화한다.
