## Stack

Isaac Sim · PhysX · OpenUSD · UR10 · Conveyor · Miniload · AMR · PLC Emulator · ROS2 · MQTT · REST

## Architecture

1. WMS 주문·재고·랙 주소
2. WCS 작업 할당·큐·인터록
3. PLC Emulator와 설비 I/O 계약
4. UR10·컨베이어·미니로더·AMR 물리 모델
5. 처리량·충돌·낙하·과적재 계측

Feedback: 자동 시나리오에서 발견한 인터록·타이밍·물리 문제를 WCS 시퀀스, PLC I/O, 설비 파라미터와
레이아웃으로 되돌린다.

## Problem

개별 설비의 동작 검증만으로는 물류 운영을 보증할 수 없었다. 컨베이어의 축적, UR10의 pick 타이밍,
미니로더의 랙 주소, AMR의 도착 시점은 서로 다른 제어기와 시간축을 갖는다. 실제 현장에서는 이
경계에서 박스가 떨어지거나 큐가 막히고, 인터록이 서로를 기다리는 교착이 생긴다.

## Environment

입고 흐름은 컨베이어→UR10 pick→미니로더 저장, 출고 흐름은 미니로더→UR10 place→컨베이어→AMR
픽업으로 구성했다. 각 설비의 물리 거동과 함께 WMS 주소, WCS 작업, PLC I/O, MQTT·REST 통신을
같은 테스트베드에 연결했다.

## Simulation

설비 모델을 한 장면에 놓는 것보다 인터페이스 계약을 먼저 고정했다. PLC Emulator가 JSON 시나리오를
OPC UA 형태의 설비 상태로 내보내고, WCS는 실제와 같은 상태 전이를 보며 다음 작업을 결정한다.
물리 장면에서는 마찰·관성·접촉·충돌을 실행하고, 운영 계층에서는 버퍼·큐·타임아웃·인터록을 실행했다.

## Verification

정상 입출고뿐 아니라 충돌, 낙하, 과적재, 설비 지연, 빈 슬롯, 센서 상태 불일치 같은 edge case를
자동 시나리오로 반복했다. 성공 여부는 영상이 끝까지 도는지가 아니라, 각 단계의 상태 계약과 물리적
인수 조건을 모두 통과했는지로 판정해야 한다. 현재 자료의 1,000+·98%·85건은 공개 전에 테스트 목록과
판정 로그를 다시 연결한다.

## Result

개별 설비 데모를 하나의 운영 검증 환경으로 바꾸었다. 현장에서 처음 연결할 때 발견될 문제를 물리,
제어, 통신, 운영 시퀀스 중 어느 계층의 문제인지 분리할 수 있게 되었고, 실제 설비 없이 WCS/WMS
변경을 반복 시험할 기반을 만들었다.

## Engineering Notes

- 설비 네 대가 각각 동작하는 것과 하나의 주문이 끝까지 처리되는 것은 다른 검증이다.
- 가상 PLC는 화면용 애니메이션이 아니라 실제 상위 시스템이 대화할 계약의 대역이어야 한다.
- 물리 실패와 운영 시퀀스 실패를 같은 성공률로 뭉개지 않고 계층별로 분류한다.
- 처리량 최적화 전에 교착·충돌·낙하가 재현되는 실패 시나리오를 먼저 고정한다.
