## Stack

Meta Quest 3 · OpenXR · Unity · ROS2 · HOVER · Isaac Sim · Behavior Cloning · PPO/SAC · Python

## Architecture

1. Meta Quest 3 인간 시연 수집
2. Unity/OpenXR 좌표·스켈레톤 변환
3. 노이즈 제거·시간 동기화·이상치 제거
4. 인간→로봇 리타게팅과 Isaac Sim 증강
5. 정책 학습·성공률 평가와 실패 데이터 재수집

Feedback: 정책 실패 조건과 관절 한계·충돌 결과를 시연 수집 범위, 필터, 리타게팅 제약과 domain
randomization 설정으로 되돌린다.

## Problem

모방학습의 병목은 모델 학습보다 시연 데이터 생성이었다. 전용 장비는 비싸고, 인간 스켈레톤을 로봇
관절로 옮기는 과정에는 좌표계·자유도·관절 한계·시간 동기화 문제가 연속해서 발생한다. 각 단계를
수작업으로 처리하면 데이터가 늘수록 같은 오류를 반복하게 된다.

## Environment

Meta Quest 3와 OpenXR로 머리·손·몸 데이터를 받아 Unity에서 스켈레톤을 구성했다. 관절 데이터와
비전 프레임을 ROS2로 동기화하고, HOVER IK/FK solver와 Isaac Sim 휴머노이드 모델에 연결했다.
데이터는 30 Hz 궤적, JSON/Parquet와 학습용 tensor 형태로 전달되는 구조다.

## Simulation

수집 데이터에 Kalman filtering, timestamp 정합, 이상치 제거를 적용하고 인간 7-DOF 표현을 로봇의
관절 구조로 리타게팅했다. 관절 한계와 충돌을 통과한 궤적만 학습 데이터로 넘기고, Isaac Sim에서
domain randomization으로 조건을 확장했다. 데이터 생성과 정책 학습을 분리해 같은 데이터셋을
BC·DAGGER·RL fine-tuning에서 비교할 수 있게 했다.

## Verification

단계별로 원본 시연, 정제 데이터, 리타게팅 관절각, 시뮬레이터 포즈와 정책 실행 결과를 대조해야 한다.
정책 성공률은 태스크 정의, 초기 조건 분포, 성공 판정과 평가 횟수가 함께 있어야 공개 가능한 지표가
된다. 현재 85%·96%·95% 주장은 이 평가 프로토콜을 연결하기 전까지 후보 값으로 둔다.

## Result

VR 시연에서 로봇 정책 평가까지 이어지는 한 개의 반복 가능한 데이터 경로를 만들었다. 데이터 50개를
수집해 자동 전처리·리타게팅하고 시뮬레이션에서 10배로 확장하는 구조를 세웠다. 사업적으로 중요한
결과는 특정 정책의 최고 성공률보다, 한 명의 엔지니어가 실패 데이터를 다시 수집해 다음 학습으로
되돌릴 수 있는 폐루프를 만든 것이다.

## Engineering Notes

- 값과 영상은 같은 시간축을 가져야 시연 데이터가 된다.
- 인간과 로봇의 자유도 차이는 스케일링이 아니라 제약이 있는 최적화 문제다.
- 증강 데이터 수보다 어떤 실패 조건을 추가했는지가 재현성에 더 중요하다.
- 성공률에는 평가 시나리오·초기 분포·표본 수·성공 조건이 함께 따라가야 한다.
