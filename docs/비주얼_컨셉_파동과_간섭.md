## 1. 왜 파동인가 — 장식이 아니라 우리 일의 구조

가이드 §21 은 "AI 버즈워드만 가득한 홈페이지"와 "의미 없는 애니메이션"을 금지한다.
그러니 이 컨셉은 **예뻐서** 채택한 것이 아니라는 근거가 먼저 있어야 한다.

우리가 파는 것은 이것이다.

> **실물을 만들기 전에, 가능한 결과들을 한꺼번에 펼쳐 놓고 그중 무엇이 실제로 성립하는지 가린다.**

이 문장의 구조가 파동 현상의 구조와 같다.

- 시뮬레이션은 **아직 확정되지 않은 여러 가능성**을 동시에 다룬다 — 여러 자세, 여러 궤적, 여러 파라미터.
- 조건들이 겹치면 어떤 결과는 **살아남고(보강)** 어떤 결과는 **사라진다(상쇄)**.
- 검증은 그 펼쳐진 가능성을 **하나의 확정된 답으로 좁히는 행위**다.
- 실물 제작은 그 답을 **되돌릴 수 없게 만드는 순간**이다.

그래서 이 사이트의 핵심 문장 **"Build in Simulation. Validate Before Reality."** 는
파동의 언어로 다시 쓰면 **"확정되기 전에 전부 펼쳐 보고, 확정은 마지막에 한다"** 가 된다.

형태 언어가 카피와 같은 말을 하고 있으면 그건 장식이 아니다.

## 2. 개념 사전 — 물리 ↔ 우리 일

**이 표가 이 문서의 핵심이다.** 새 비주얼을 만들 때, 그 형태가 이 표의 어느 줄을 표현하는지
답할 수 없으면 만들지 않는다.

| 물리 개념                         | 우리 일에서 대응하는 것                                           | 근거 (실제 수행)                                   |
| --------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------- |
| **파동 (wave)**                   | 아직 확정되지 않은 가능성의 장 — 가능한 자세·궤적·파라미터의 집합 | 도달 범위·작업 영역 해석                           |
| **간섭 (interference)**           | 조건이 겹쳐 결과가 갈리는 것. 되는 영역과 안 되는 영역이 나뉜다   | 도달 가능/불가 영역 판정                           |
| **보강 간섭 (constructive)**      | 조건이 맞아떨어져 해가 존재하는 구간                              | 전 구간 역기구학 해 확보                           |
| **상쇄 간섭 (destructive)**       | 조건이 서로를 지워 **해가 사라지는 구간**                         | 특이 자세 dead-band — 관절해 없음                  |
| **마디 (node)**                   | 아무리 세게 밀어도 반응이 없는 지점                               | 자코비안 조건수가 폭발하는 자세                    |
| **경로차 (path difference)**      | 두 경로가 만들어 낸 차이. 작아 보여도 결과를 가른다               | 모델과 실기의 차이, 관절보간과 직선의 이탈량       |
| **위상 (phase)**                  | 같은 크기라도 **시점이 어긋나면** 결과가 달라진다                 | 다축 동작에서 속도비가 깨지는 문제, 제어 주기 지연 |
| **파면 (wavefront)**              | 가능성이 퍼져 나가는 경계                                         | 작업 영역의 경계면                                 |
| **공진 (resonance)**              | 특정 조건에서 증폭되어 시스템을 무너뜨림                          | 제어 게인과 지연이 만든 한계진동                   |
| **측정 · 확정 (measurement)**     | 검증. 펼쳐져 있던 가능성이 **하나의 값으로 확정**된다             | 계측·검증 리포트                                   |
| **되돌릴 수 없음 (irreversible)** | 실물 제작. 여기서부터 수정 비용이 폭발한다                        | "Validate **Before** Reality" 의 Before            |

> **양자역학 용어의 취급**: 중첩·측정·붕괴 같은 표현은 **은유로만** 쓴다.
> 우리는 양자 컴퓨팅을 하지 않는다. 물리적으로는 고전 파동(간섭·정상파·공진)이 정확한 비유이고,
> "확정 전 가능성의 장"이라는 정서적 울림만 양자 쪽에서 빌려온다.
> **사이트 카피에 "양자"라는 단어를 쓰지 않는다** — 쓰는 순간 §21 이 금지한 버즈워드가 된다.

## 4. 형태 어휘 (form vocabulary)

**어휘를 고르는 기준은 개수가 아니라 파원 구성(source configuration)이다.**

초판에서는 "네 가지만 쓴다"로 정했다. 페이지가 늘면서 그 수를 넘겼는데,
단순히 상한을 올리면 규칙이 없어진다. 그래서 **세는 규칙을 구조 규칙으로 바꾼다.**

> **파원이 몇 개이고 어떻게 놓였는가** — 그것이 형태를 가른다.
> 같은 구성에서 파라미터만 바꾼 것은 **새 형태가 아니다**(변주).
> 물리적으로 다른 구성이면 새 형태이고, §2 대응표에 자리가 있어야 채택한다.

| 파원 구성               | 형태        | 뜻 (§2)                      |
| ----------------------- | ----------- | ---------------------------- |
| 단일 파원 · 고리        | `RING`      | 가능성의 장                  |
| 단일 파원 · 퍼지는 파면 | `WAVEFRONT` | 작업 영역의 경계             |
| 단일 파원 · 정상파      | `NODE`      | 해가 사라지는 지점           |
| 무한히 먼 파원 (평면파) | `PLANE`     | 방향이 하나로 정해진 결      |
| 움직이는 파원 (V 파)    | `BOW`       | 시작점에서 퍼져 나감         |
| 두 점 파원              | `FRINGE`    | 조건이 겹쳐 결과가 갈림      |
| 두 직교 평면파          | `LATTICE`   | 두 조건이 동시에 걸리는 격자 |

**일곱 가지가 파동의 기본 구성을 거의 다 덮는다.** 여기서 더 늘릴 자리는 사실상 없다 —
새 형태를 만들려면 먼저 "이건 어떤 파원 구성인가"에 답해야 하고, 위 표에 없는 구성이어야 한다.

### ① 고리 — 토로이달 발광체 `RING`

- 뜻: **가능성의 장.** 아직 확정되지 않은, 중심을 가진 에너지.
- 구현: 중심 거리 기반 가우시안 고리 두 개를 겹치고 각도별로 밝기를 달리한다.
- 쓰는 곳: **히어로** — 사이트의 첫 진술. "여기서부터 가능성을 펼친다."
- **수평 변주**: 좌표계의 세로를 크게 곱하면(`squash`) 원이 가로로 긴 타원이 되고
  고리의 호가 수평 띠처럼 읽힌다. **About 페이지 배경**이 이것이다 —
  첫 화면과 같은 말을 하되 페이지 전체 배경이므로 눕혔다. 새 형태가 아니다.

### ② 프린지 — 두 파동원의 간섭 무늬 `FRINGE`

- 뜻: **조건이 겹쳐 결과가 갈리는 것.** 밝은 띠는 성립, 어두운 띠는 소멸.
- 구현: 두 점까지의 경로차를 코사인에 넣는다 — `cos((d₁ − d₂) · k)`.
- 쓰는 곳: **마무리 CTA(Call To Action)** — "당신의 조건을 넣으면 무엇이 남는지 보여주겠다."

### ③ 마디 — 정상파의 노드 `NODE` ✅

- 뜻: **해가 사라지는 지점.** 특이 자세 · dead-band.
- 구현: 중심에서 퍼지는 발광 위에 `|cos(kr)|` 로 **어두운 띠를 새긴다.**
  빛나는 고리가 아니라 **빛이 끊기는 자리**가 주인공이다.
- 쓰는 곳: **Services 페이지 전체 배경** — 되는 곳과 안 되는 곳을 가르는 서비스.

### ④ 파면 — 퍼져 나가는 경계 `WAVEFRONT` ✅

- 뜻: **작업 영역의 경계.** 여기까지는 닿고 그 너머는 못 닿는다.
- 구현: 한 점에서 퍼지는 동심 호를 부채꼴로 제한하고 거리에 따라 감쇠시킨다.
  사방으로 퍼뜨리면 동심원 과녁이 되어 형태가 죽는다.
- 쓰는 곳: **Technology 페이지 배경** — 발원점을 화면 안에 두어 중심이 보인다.

### ⑤ 평면파 — 일자 수평파 `PLANE` _(구현했다가 교체됨)_

- 뜻: 파면에서 **곡률이 사라진 상태.** 파원이 무한히 멀어 방향이 하나로 정해진다.
- About 배경으로 한 번 적용했다가, 히어로와 같은 말을 하도록 **`RING` 의 수평 변주로 교체**했다.
  띠만 남으면 사이트 첫 화면과의 연결이 끊긴다는 판단이다.
- 어휘 표에는 남겨 둔다 — 파원 구성으로서는 유효하고, 필요해지면 다시 쓸 수 있다.

### ⑥ 뱃머리파 — V 파 `BOW` ✅

- 뜻: **시작점이 있고 거기서부터 퍼진다.** 움직이는 파원이 뒤로 남기는 쐐기.
- 구현: 꼭짓점에서 `|y| − (꼭짓점까지 거리)·기울기` 를 위상으로. 꼭짓점 **바깥쪽은 비운다** —
  파원이 아직 지나지 않은 자리다.
- **방향**: 꼭짓점을 오른쪽에 두어 화살표가 **오른쪽(전진)** 을 가리킨다.
  부호 하나(`behind = -x`)가 방향을 정한다.
- 쓰는 곳: **Contact 페이지 배경** — "START A PROJECT", 무언가가 출발하는 자리.

### ⑦ 격자 간섭 — 두 직교 평면파 `LATTICE` ✅

- 뜻: **두 조건이 동시에 걸리는** 간섭. 밝은 점은 둘 다 성립한 지점,
  어두운 마디는 하나라도 어긋난 지점이다.
- 구현: `|cos(kx) · cos(ky)|`. 봉투로 감싸지 않으면 화면을 덮어 방충망이 된다.
- 쓰는 곳: **Projects 페이지 배경** — 계측 격자처럼 읽힌다. "무엇이 확인되었는가"의 자리.

### ⑧ 유령 파원 — 자리가 빈 두 파원 `PHANTOM SOURCE` ✅

- 뜻: **결과의 장은 온전한데 원인의 자리가 비어 있다.** 그리고 그것이 둘이다.
  컨트롤러 펌웨어가 로봇 없이 도는 상태 — 몸은 없고 법칙만 있는 기계 — 를 형태로 옮긴 것이다.
  두 파원은 같은 파수·같은 위상이므로 **어느 쪽이 원본인지 장을 보고는 알 수 없다.**
  가상 컨트롤러와 실기 컨트롤러가 근사가 아니라 같은 법칙이라는 뜻이고, 그것이 이 구조의 목표다.
- 구현: 진폭을 더한 뒤 제곱한다(`(cos(k·r₁)/√r₁ + cos(k·r₂)/√r₂)²`) — 세기를 더하면 간섭이 사라진다.
  그다음 **두 파원 자리를 도려낸다**(가우시안 역마스크). 다른 형태가 중심을 발광시키는 것과 정반대다.
- 쓰는 곳: **컨트롤러 인더루프 케이스 스터디의 대표 이미지.**
  페이지 배경으로는 쓰지 않는다 — 무늬가 촘촘해 본문을 방해한다.

> 형태 모두 **정지 이미지**다. 움직이지 않아도 뜻이 전달되어야 한다.
> 스크롤 리빌(페이드 인) 외의 모션을 붙이지 않는다.

### 축척에 따른 재작도

같은 형태라도 **크기가 바뀌면 다시 그린다.** 어휘가 늘어나는 것이 아니라 같은 글자를 다른 크기로 쓰는 것이다.

파비콘이 그 사례다. 히어로의 부드러운 광채를 16px 로 줄이면 회색 얼룩이 된다.
그래서 아이콘용 `RING` 은 **고리를 두껍게, 블러를 약하게, 대비를 세게** 하고 그레인을 빼서
`build_icon_field()` 로 따로 그린다. 형태의 뜻(가능성의 장)은 그대로다.

## 5. 색 · 노출 규칙

상위 문서 §2 의 무채색 원칙을 깨지 않는 선에서, **단일 초록**만 쓴다.

| 항목           | 값                                                        |
| -------------- | --------------------------------------------------------- |
| 그림자         | `#030907` — 사이트 배경(`#08090a`)과 붙어 경계가 사라진다 |
| 중간           | `#0a3424` → `#1e845a`                                     |
| 하이라이트     | `#60d898` → `#c2fada`                                     |
| UI 액센트      | `#74eeae` — 같은 계열로 맞춘다                            |
| 밝은 화소 비율 | **전체의 20% 이하** — 넘으면 배경이 아니라 그림이 된다    |

현재 배경 자산 측정값(휘도 48 초과 화소 비율):

| 자산               | 평균 휘도 | 밝은 화소 |
| ------------------ | --------- | --------- |
| about-field        | 14.7      | 6.2%      |
| technology-field   | 13.6      | 3.5%      |
| contact-page-field | 14.1      | 5.0%      |
| projects-field     | 16.0      | 5.2%      |
| services-field     | 19.6      | 8.1%      |

> `services-field` 는 처음에 **26.4%** 로 이 상한을 넘겼다(§9 실패 기준 2번).
> 감마를 1.15 → 1.60 으로 올리고 발광 반경을 줄여 8.1% 로 낮췄다.
> **상한은 눈이 아니라 숫자로 확인한다** — 어두운 화면에서는 감이 쉽게 틀린다.

- 사진 자산도 같은 초록 듀오톤으로 통일한다(→ [미디어_자산_명세서](미디어_자산_명세서.md) §4-1).
- 그레인은 필수다. 매끈한 그라디언트는 밴딩이 생기고 CG(Computer Graphics) 티가 난다.
- **초록 외의 색을 추가하지 않는다.** 두 번째 색이 들어오는 순간 이 언어는 무너진다.

## 6. 카피 규칙

이 컨셉에서 **나오는 말**:

- 확정 / 검증 / 성립 / 소멸 / 경계 / 조건 / 차이
- "확정되기 전에" · "무엇이 남는지" · "되는 곳과 안 되는 곳"

**나오면 안 되는 말**:

- 양자, quantum, 초월, 무한, 혁신, 차세대
- 형태를 설명하는 말 — 화면에 "이것은 간섭 무늬입니다"라고 쓰지 않는다. 형태는 스스로 말하거나 침묵한다.

> 카피는 여전히 짧다(디자인 §7). 이 컨셉은 **말을 늘리는 근거가 아니라 형태를 고르는 근거**다.

## 7. 페이지별 적용 계획

| 위치                            | 형태        | 상태                                      |
| ------------------------------- | ----------- | ----------------------------------------- |
| 홈 히어로                       | `RING`      | ✅ 적용                                   |
| 파비콘 · 앱 아이콘              | `RING`      | ✅ 적용 (작은 크기용 재작도)              |
| 홈 마무리 CTA                   | `FRINGE`    | ✅ 적용                                   |
| About 페이지 배경               | `RING`      | ✅ 적용 (수평 변주 — 히어로와 같은 형태)  |
| Contact 페이지 배경             | `BOW`       | ✅ 적용 (V 파 — 오른쪽 방향)              |
| Services 페이지 배경            | `NODE`      | ✅ 적용 (해가 사라지는 지점)              |
| Projects 페이지 배경            | `LATTICE`   | ✅ 적용 (두 직교 평면파)                  |
| Technology 페이지 배경          | `WAVEFRONT` | ✅ 적용 (발원점 화면 안)                  |
| **Projects 케이스 스터디 슬롯** | —           | **형태 금지.** 실제 결과물만 (디자인 §14) |

### 페이지 배경과 케이스 스터디 슬롯은 다르다

이전 판에서 "Projects 에는 형태를 넣지 않는다"고 적었는데, 그 금지는 **케이스 스터디의 이미지 자리**를 뜻한다.
거기에 추상 형태를 넣으면 실적을 그림으로 대신하는 것이 되어 §14 위반이다. 그 금지는 그대로 유지한다.

**페이지 배경은 다른 층이다.** 배경은 무엇을 했다고 주장하지 않는다.
그래서 Projects 페이지에도 배경은 둘 수 있다.

**케이스 스터디 슬롯 (2026-08-13 완화)** — 원칙은 "실제 결과물만"이다. 다만 캡처가 없는 동안
플레이스홀더가 "media pending" 문구로 노출되어 미완성으로 보이는 문제가 있었다.
그래서 **다음 조건을 모두 만족할 때만** 추상 텍스처를 허용한다.

1. **사진처럼 보이지 않을 것** — 강한 블러로 형상을 알아볼 수 없게 만든다.
   형상이 남으면 보는 사람이 그것을 실적으로 읽는다. 이것이 유일하게 중요한 조건이다.
2. 실제 캡처가 준비되면 **즉시 교체**한다(debt-008 로 추적).
3. 실제 캡처가 있는 케이스는 **건드리지 않는다.**

생성은 [scripts/gen-case-textures.py](../scripts/gen-case-textures.py) 가 하고,
슬러그 해시로 20종 중 하나가 결정적으로 배정된다 — 케이스가 늘어도 손으로 고르지 않는다.

Projects 배경은 `RING` 을 쓰되 **코어를 주인공으로** 한다 — §2 의 _측정 · 확정_,
펼쳐져 있던 가능성이 하나의 값으로 좁혀진 상태다. 새 어휘가 아니라 강조점을 옮긴 것이다.

## 8. 생성 파이프라인

전부 [scripts/gen-fields.py](../scripts/gen-fields.py) 한 파일에서 나온다.

```bash
python3 scripts/gen-fields.py
```

- 원본 사진이 **없다.** 픽셀을 수식으로 계산한다 → 라이선스 자유, 색 정확, 재현 가능.
- 형태를 추가하려면 `build_*_field()` 함수를 하나 더 쓰고 `main()` 에 등록한다.
- 램프 · 그레인 · 블러는 공유한다. **형상 함수만 다르다** — 이것이 형태들이 한 가족으로 보이는 이유다.
- 새 형태를 추가할 때는 **§2 표의 어느 줄인지 함수 docstring 에 쓴다.** 못 쓰면 만들지 않는다.
- 어떤 이미지가 어느 함수·파라미터에서 나왔는지는 [scripts/자산_맵.md](../scripts/자산_맵.md) 가 단일 대조표다.

### 같은 형태의 변주는 새 어휘가 아니다

Contact 페이지 배경은 홈 CTA 와 **같은 `FRINGE`** 다. 파장을 넓히고 밝기를 낮췄을 뿐이다 —
같은 말을 작은 목소리로 하는 것이다. 페이지 전체 배경은 섹션 배경보다 조용해야 하므로
새 형태를 만들지 않고 기존 형태의 노출만 바꾼다. 파비콘의 축척 재작도와 같은 원리다.

## 8-1. 콘셉트 탐색 자산 (채택 전)

사이트에 쓰기 전 형태를 탐색하는 이미지는 [scripts/gen-concept.py](../scripts/gen-concept.py) 로 만들고
`image/concept/` 에 **쌓아 둔다.** 덮어쓰지 않는다 — 탐색 과정 자체가 자산이다.

```bash
python3 scripts/gen-concept.py --form burst --seed 41 --teeth 220
```

파일명에 형태·번호·시드가 들어가 언제든 같은 그림을 다시 만들 수 있다(`burst-002-seed41.webp`).
무손실 PNG 대신 고품질 WebP 로 저장한다 — 스크립트와 시드가 원본 역할을 하므로 손실이 문제되지 않고,
저장소가 가벼워진다.

| 형태      | 뜻 (§2 대응)                                                  | 상태          |
| --------- | ------------------------------------------------------------- | ------------- |
| `ring`    | `RING` 을 발광체가 아니라 **구조물**로 옮긴 변형              | 탐색 — 미채택 |
| `burst`   | **파면(wavefront)** — 중심에서 퍼져 나가는 경계               | 탐색 — 미채택 |
| `fractal` | **간섭** 과 같은 자리 — 수렴/발산이 갈리는 경계의 무한 세밀도 | 탐색 — 미채택 |

> 세 형태 모두 §2 대응표에 자리가 있지만 **아직 §4 형태 어휘에 넣지 않았다.**
> 사이트에 쓰기로 결정할 때 어휘로 승격하고, 그때 4종 제한을 다시 따진다.

## 9. 이 컨셉이 실패했다고 판단할 기준

자기점검용이다. 하나라도 해당하면 되돌린다.

1. 방문자가 형태를 보고 **"예쁘다" 외에 아무 말도 못 한다** → 근거 없는 장식이 됐다.
2. 밝은 화소가 20% 를 넘어 **텍스트보다 배경이 먼저 읽힌다** → §2 위반.
3. **§4 표에 없는 파원 구성**의 형태가 생겼다 → 어휘가 아니라 소음.
   (초판은 "5종 이상"이라는 개수 기준이었다. 페이지가 늘며 그 수를 넘겼고,
   상한만 올리면 규칙이 사라지므로 **구조 기준으로 바꿨다.** 개수가 아니라
   "파원 구성이 물리적으로 다른가"가 판정 기준이다.)
4. 카피에 "양자"·"파동" 같은 물리 용어가 등장한다 → 은유가 주장으로 넘어갔다.
5. 실제 시뮬레이션 영상이 준비됐는데도 추상 형태를 히어로에 유지하고 있다 → **§14 위반**. 실물이 있으면 실물이 이긴다.

> 5번이 가장 중요하다. 이 컨셉은 **자산이 없는 동안의 언어**이며,
> 실제 엔지니어링 결과물이 준비되면 그쪽에 자리를 내주는 것이 원래 설계다(debt-007).
